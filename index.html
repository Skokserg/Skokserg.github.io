Personal cloud file migration

A self-hosted workflow to copy personal files from Yandex Disk to Google Drive using the open-source rclone tool.

The utility runs on a privately administered server. This website provides information about the utility and its data practices. It does not provide public account registration, sign-in, or file-upload features.

Read privacy policyRead terms

How it works

01

Authorize accounts

The account owner authorizes access to their Yandex Disk and Google Drive accounts through the providers' supported authentication methods.

02

Copy files

The utility transfers files through an owner-managed virtual private server over encrypted connections, preserving the destination folder structure.

03

Verify the copy

File names, sizes and available checksums are used to assess transfer success. Source files are not intentionally deleted by the migration workflow.

Why Google Drive access is requested

The utility needs to create and inspect files in the destination Drive. Full Google Drive access may be requested so a new OAuth client can see files created earlier by a different OAuth client. This is broader permission than the everyday copy operation requires.

The permission is used for migration and integrity checks, not to operate a public file-sharing service.

Data handling

Authentication tokens are held on the private server, not on this website. File contents pass through the server during transfer; operational logs can contain file paths, transfer sizes, statuses and errors.

There is no advertising, tracking script or sale of user data associated with this site or migration utility.

Personal use only

This utility is maintained for the owner's own cloud accounts; it is not offered to other users as a hosted service. The account owner controls the migration server, target Drive folder, OAuth permissions and credential revocation.

For information about access, use, storage, and deletion of Google user data, see the Privacy Policy.
